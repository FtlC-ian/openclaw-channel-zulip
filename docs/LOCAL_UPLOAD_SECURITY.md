# Local upload policy

Local paths and file:// URLs require a host-provided media root (`mediaAccess.localRoots` or `mediaLocalRoots`) or an explicit per-account `media.localRoots` allowlist. Roots are additive; configure only directories you intend the agent to export. No implicit workspace, home, or filesystem root is allowed. Absolute roots and files are canonicalized with realpath before containment checks. An invalid root fails closed.

`channels.zulip.media.localUploads` defaults to true, but does not authorize any path by itself; false disables all local uploads. `channels.zulip.media.localRoots` defaults to []. These settings are also accepted under `channels.zulip.accounts.<accountId>`. Account-level media replaces the inherited media object, consistent with existing account config merging.

Local outbound size uses account `mediaMaxMb`, then agents.defaults.mediaMaxMb, then 5 MB. A regular-file check and inode/device comparison protect against file replacement between validation and open; O_NOFOLLOW rejects a final-component symlink swap. The descriptor read is capped at maxBytes+1 and closed before upload. A private temporary copy is removed even if upload fails. Host read callbacks are not used for local files: they cannot replace realpath/size enforcement. HTTP(S) handling is unchanged.

Example opt-in: `"media": { "localRoots": ["/absolute/export-directory"] }`. To deliberately restore the old unrestricted filesystem scope, `"media": { "localRoots": ["/"] }` is available but strongly discouraged: it authorizes export of every readable regular file subject to the size cap. Prefer workspace and output directories.

Structural constraints: host SDK loader remains used for remote URLs when host access is supplied; local authorization is owned by sendMessageZulip rather than an optional SDK seam. Zulip account resolution and remote/upload APIs remain unchanged. Roots are administrative configuration, not message input. Concurrent hostile directory renames by another local process are outside this policy (the host filesystem must not be adversarially modified during validation).

Test-value audit: sendMessageZulip is the primary boundary. Real temporary filesystem cases prove out-of-root, traversal, symlink escape, absent-root, disable switch, oversized-file rejection and host/account in-root success. Upload mocks prove absence of upload side effects, not server behavior. Existing remote and hosted-URL tests independently protect compatibility. No test-only production seam was added. Security regression evidence uses account-configured roots with no host media callback/root options, exercising the formerly unguarded direct-upload branch. Against original send.ts all six denial scenarios resolve successfully (uploads occur), rather than rejecting; restoring guarded code makes all six pass. Disabled and size cases use otherwise permitted in-root files, so neither can pass merely because containment denies them. The policy document is explicitly included in the published package files.
